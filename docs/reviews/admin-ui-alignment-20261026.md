# Threads管理画面の統一 — 2026-10-26

LINE/IGの共通構成を基準に、Threadsの管理画面を左サイドバー・操作中アカウント切替・ページ見出し・カード・Kumoボタン/状態バッジに揃えました。Threadsのブランドはモノクロとし、他SNSのコードや配信設定は変更しません。

## 画面構成

- ダッシュボード: 選択アカウントの全件集計、最近の原稿、投稿枠、接続。
- 投稿管理: 状態フィルタ、本文検索、連投のグループ表示、全文と素材順の公開確認。
- 新規投稿: テキスト・連投・画像・動画・混在カルーセル。内容プレビューと下書き保存。
- 予約一覧: 公開待ち/準備中/処理中/公開中。日時を「公開処理の開始日時」として案内。
- インサイト: 保存済み6指標の集計と投稿ごとの再取得。未知の数値は「—」。
- アカウント設定: 接続、期限・権限確認、予約再開、切断。

幅1024px未満では上部メニューとモバイル用ダイアログを使用。レイアウトは画面幅に応じて1列へ切り替え、表は横スクロール可能にしています。

SSOセッションは自動で読み込みます。原稿は画面移動中にメモリ内で保持し、アカウント切替・破棄・ログアウトでは未保存確認を行います。公開前は投稿先・連投全件・添付順・日時を確認し、内容が途中で変わった場合は再確認を求めます。公開ボタンを連打しても、同じ処理の完了まで追加送信しません。サーバー側の原稿状態チェック・DOの二重送信防止は維持します。

## 集計と保存

新しい認証付き `GET /api/overview?accountId=...` は、選択アカウントの非表示を除く原稿を全件集計します。最新200投稿の一覧制限とは独立しています。非表示の投稿はインサイト集計からも除外します。トークン・投稿履歴・既存予約の変更やmigrationの追加はありません。

## 検証

- メモリ内DOMで13ケース: SSO自動ログイン、初回接続、画面切替、メディア下書き保存、未保存保護、連投全件確認、二重クリック防止、レビュー後の変更拒否、日時指定、0/未取得の区別、モバイルメニュー、認証拒否、非表示確認、遅延応答後のログアウト保持、スキップリンク（複数の確認を含む）。
- Worker集計: アカウント分離・非表示除外・200件超の件数・未計測値を確認。
- 全体120テスト、型チェック、Viteビルド、Python 3テスト、workerd/DOのAPIと既存メディア処理の検証。
- ブラウザ/Playwright/Computer Useは使用していません。実機でのピクセル単位の見た目・レイアウト確認は未実施です。
- 本作業のための実SNS投稿は行いません。
