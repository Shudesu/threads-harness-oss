# 06 日常運用とログ

- 下書き: アカウントを選び、1〜500文字で保存。下書き保存だけでは公開しません。
- 連投: 「連投を作成」を選び、改行した `---` で2〜10件に分割。先頭からまとめて予約・取消・非表示します。
- 予約: 保存後に日時を指定し「予約する」。画面の日時は端末のローカル時刻です。空欄で「公開する」を押すと順次送信します。
- 取消: 処理前の公開待ちのみ。処理開始後は取り消せません。
- 非表示: 下書き・公開済みを一覧から隠します。Threads上の投稿削除ではありません。
- インサイト: 公開済みの記事で取得。未取得の数値は0にせず「未取得」と表示します。

`failed` はコンテナ作成前の明確な拒否や期限切れで、公開に至っていない状態です。原因を直してから新しい下書きで準備します。

`needs_review` は成否不明または処理が停止した状態です。診断コードとThreads上の公開結果を確認してください。後続連投も停止し、自動再送しません。新規の原稿として再投稿する前に、重複の有無を必ず確認します。

新しい予約はアカウントごとのDOが処理し、既存予約は従来のtenant DOが処理します。空のキューではDOアラームを停止します。未来の予約はその時刻まで待機し、新規投入で再起動します。処理中のジョブは状態確認・障害復旧用の起動を残します。

## ログと保持

`observability.enabled=true` でWorkers Logsを有効にします。認証URLの保存を避けるためinvocation logsは無効にし、明示的な診断イベントだけを記録します。コード・例外全文・トークン・リクエストURL・上流レスポンス本文をログに追加しないでください。

保存日数と上限は[Cloudflare Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/)の契約プランに従い、配備先で確認します。この設定だけで無期限保存にはなりません。長期保管が必要なら、秘密除去済みの障害記録だけをアクセス制限した場所へ保存し、運営者が保持期限を決めます。D1の下書き・会話に関する所有データ・投稿履歴は自動削除しません。

WFPでは配備側もobservability設定を反映する必要があります。バンドルを生成しただけで既存テナントのログ設定は変わりません。
