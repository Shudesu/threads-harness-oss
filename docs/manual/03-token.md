# 03 トークンの交換と期限管理

短命Threadsユーザートークンは1時間、長期トークンは60日です。貼り付け直すだけでは期限は延びません。取得方法だけで寿命を決めつけず、Metaが返す `expires_in` または `expires_at` を確認してください。

## 長期トークンへの交換

**まずDebuggerで実際の期限を確認してください。長期トークンなら交換は不要です。未失効の短命トークンの場合だけ**、信頼できるローカル端末またはサーバーから `GET https://graph.threads.net/access_token` を呼びます。

| パラメータ | 値 |
|---|---|
| grant_type | th_exchange_token |
| client_secret | **Threads App Secret**（通常のMeta App Secretとは別） |
| access_token | 未失効の短命ユーザートークン |

[公式手順とリクエスト例](https://developers.facebook.com/documentation/threads/get-started/long-lived-tokens.md)を使います。秘密をURL付きのシェル履歴やプロセス引数へ直接書かず、サーバー側の秘密ストアから読み込むか、手元の対話入力で渡してください。HTTPデバッグ出力やURLの記録を無効にします。戻り値の `access_token` を安全に保管し、発行時刻と `expires_in` から期限を記録します。ブラウザJSにアプリシークレットを埋め込まないでください。

既に長期のトークンを再交換した場合や資格情報を取り違えた場合は、452 / 4279019などで拒否されたという報告があります。コードだけで原因を断定せず、トークンの期限・種類とThreads App Secretを確認してください。

## 更新・再接続

長期トークンは発行または更新から24時間以上経過し、**未失効であること**が更新条件です。`GET /refresh_access_token` に `grant_type=th_refresh_token` と現在の長期 `access_token` を渡します。更新後の60日は更新実行日から数えます。返却されたトークンと期限を保存し、管理画面に貼り直してください。失効済みなら新規発行からやり直します。

この製品は自動更新しません。管理画面は確認できた実期限を保存し、7日前から案内、期限切れでは予約・送信を止めます。トークン期限とデータアクセス許諾期限は別です。どちらかが切れても再認証が必要です。未確認・0の期限は「不明」と表示し、60日を推定で補いません。

APIからの失効検出は「接続状態を確認」、投稿、インサイト取得時です。常時監視や外部通知ではありません。期限が不明ならMetaで確認し、定期的に接続を確認してください。

## 失効時の予約

v0.1.2以降は、既知の期限切れやtoken_invalidを検出したアカウントを一時停止し、未処理の原稿をqueued/processingのまま保持します。再接続だけでは保留した予約を自動再開しません。本文・順序・予約日時・残件を確認して「残っている予約を再開」を押してください。過去の日時の原稿は順次公開されます。不要なqueued原稿は再開前に取り消します。

公開POSTの成否が不明だった原稿や過去版ですでにneeds_review/failedになった原稿は、自動でqueuedへ戻しません。Threads上の公開結果を確認してから個別に対処します。

## データアクセス許諾の期限

トークン期限とは別に、権限付与の90日期限が公式Get Startedに記載されています。公開/非公開プロフィールの延長条件は公式ページ間で記述差があるため、一律の自動延長を保証しません。`data_access_expires_at` が返る場合はその値を優先し、不明な場合は90日を目安に権限を再確認します。期限が来る前にMetaで再承認してください。
